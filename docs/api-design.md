# QuickNotes API Design

## 1. Overview

QuickNotes provides a REST API for authenticated users to create,
read, update and delete their notes. The API exchanges JSON over
HTTPS and uses bearer-token authentication.

Base URL: `https://api.quicknotes.example/v1`

All note resources belong to the authenticated user unless the
endpoint explicitly describes another scope.

## 2. Endpoints

| Method | Path | Description | Success status |
|---|---|---|---|
| POST | /auth/register | Register a user | 201 Created |
| POST | /auth/login | Authenticate and obtain a token | 200 OK |
| GET | /notes | List the authenticated user's notes | 200 OK |
| GET | /notes/{id} | Retrieve one note | 200 OK |
| POST | /notes | Create a note | 201 Created |
| PATCH | /notes/{id} | Update some fields of a note | 200 OK |
| DELETE | /notes/{id} | Delete a note | 204 No Content |
| GET | /tags | List the user's tags | 200 OK |
| POST | /notes/{id}/tags/{tagId} | Associate a tag with a note | 204 No Content |

All endpoints except registration and login require a valid
bearer token. IDs are generated by the server.

## 3. List notes

### Request

`GET /v1/notes?page=1&limit=20`

Headers:

`Authorization: Bearer <access-token>`

Optional query parameters:
- `page`: page number, starting at 1.
- `limit`: number of notes per page, from 1 to 100.
- `q`: optional search text.
